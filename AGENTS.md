# AGENTS.md: operating guide for AI agents

You are operating a **local AI image upscaler**. It enlarges JPG, PNG and WEBP
images to **200% (2x)** or **400% (4x)** with Real-ESRGAN, one image or a batch
of up to 20. Everything runs on this machine, and no image leaves it.

The target platform is **Windows** (PowerShell). The commands below are PowerShell
unless marked otherwise. Run them from the project root, the folder that contains
this file.

## 1. Folder map

| Path | What it is |
|---|---|
| `setup.ps1` | One-time install. Safe to re-run |
| `start.ps1` / `stop.ps1` | Start or stop the server (API + web UI) on port 8000 |
| `backend/app/` | FastAPI server and the Real-ESRGAN upscaler |
| `backend/agent/` | MCP server (tools for AI agents) and its HTTP client |
| `backend/models/` | Real-ESRGAN weights (`RealESRGAN_x2plus.pth`, `RealESRGAN_x4plus.pth`), already included |
| `frontend/dist/` | Pre-built web UI, served at http://localhost:8000 |
| `.mcp.json` | Claude Code MCP config, generated by `setup.ps1` |

## 2. One-time setup

**Requirements:** Windows 10/11, **Python 3.10+** on PATH (`py -3 --version` or
`python --version`), and internet access for the first `pip install` (~1-3 GB for
PyTorch). Node.js is **not** needed because the UI is pre-built. An NVIDIA GPU is
optional but much faster.

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
# For Claude Desktop, also register the MCP server in its config:
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -RegisterClaudeDesktop
```

Setup succeeded when the script ends with `Setup complete.` and the verification
line prints `torch ... | CUDA available: True/False`. `False` means it runs on the
CPU: correct, but slow. Use `-Cpu` to force the CPU build even if a GPU is present.

If Python is missing, tell the user to install it from https://www.python.org/downloads/
with **"Add python.exe to PATH"** ticked, then open a new terminal and re-run setup.
Do not try to install Python silently.

## 3. Start, check, stop

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Background   # returns when ready
Invoke-RestMethod http://localhost:8000/api/health                  # status=ok, upscaler=real-esrgan
powershell -ExecutionPolicy Bypass -File .\stop.ps1
```

- `start.ps1 -Background` returns as soon as `/api/health` answers, and exits 0 if
  the server is already running. Logs go to `backend\server.log`.
- `upscaler` must be `real-esrgan`. If it says `lanczos`, the model files are
  missing, so run `setup.ps1` again.
- The server must be running for **both** the MCP tools and the REST API.

## 4. Upscale with MCP tools (preferred)

If your client lists tools named `upscale_images`, `get_job_status`,
`download_results` and `upscaler_info` (server name `image-upscaler`), use them.

- **Claude Code:** start `claude` in this folder and approve the `image-upscaler`
  server from `.mcp.json`.
- **Claude Desktop:** run `setup.ps1 -RegisterClaudeDesktop`, then fully quit and
  reopen Claude Desktop.
- **Other MCP clients:** stdio command = `backend\.venv\Scripts\python.exe`, args =
  `backend\scripts\mcp_server.py` (both absolute paths), env `UPSCALER_API_URL=http://localhost:8000`.
  `claude_desktop_config.snippet.json` contains the exact values for this machine.

| Tool | Arguments | Result |
|---|---|---|
| `upscale_images` | `paths` (absolute paths, required), `scale` 2 or 4 (default 2), `output_dir` (absolute, optional), `overwrite` (default false), `timeout_seconds` (default 600) | `{job_id, status, results:[{input, output, status, error, size, output_size}]}` |
| `get_job_status` | `job_id` | per-file `status` (`queued`/`processing`/`done`/`error`) and `progress` 0-1 |
| `download_results` | `job_id`, `output_dir` (absolute), `overwrite` | `{saved:[paths], pending:[names], failed:{name: error}}` |
| `upscaler_info` | none | upscaler in use, scales, limits. Call it first if unsure the server is up |

Example call: `upscale_images(paths=["C:\\Users\\me\\Pictures\\cat.jpg", "C:\\Users\\me\\Pictures\\dog.png"], scale=4)`
saves `C:\Users\me\Pictures\cat_4x.jpg` and `dog_4x.png`.

Rules:
- **Use absolute paths.** Relative paths are rejected.
- Output names are `<name>_2x.<ext>` or `<name>_4x.<ext>`, in the same format as the
  input, saved next to each input unless you pass `output_dir`.
- Existing files are **never overwritten** unless `overwrite=true`. If the tool
  reports "already exists", ask the user before overwriting, or choose another `output_dir`.
- If the result `status` is `processing` (the timeout was reached), poll
  `get_job_status` every few seconds, then call `download_results`.
- Report each result's `output` path and `output_size` back to the user, and any per-file `error`.
- If a tool says "Cannot reach the upscaler API", start the server (section 3) and retry.

## 5. Upscale with the REST API (fallback, no MCP)

Base URL: `http://localhost:8000`. PowerShell 5.1's `Invoke-RestMethod` can't easily
send multipart uploads, so use **`curl.exe`**, which ships with Windows 10/11. Write
`curl.exe`, not `curl`, because `curl` is an alias for something else in Windows PowerShell.

```powershell
$ErrorActionPreference = "Stop"

# 1. Submit a batch (repeat -F for each file; scale = 2 or 4)
$job = curl.exe -s -F "scale=4" -F "files=@C:\pics\cat.jpg" -F "files=@C:\pics\dog.png" http://localhost:8000/api/jobs | ConvertFrom-Json
if (-not $job.id) { throw "Upload failed: $($job.detail)" }

# 2. Poll until done
do { Start-Sleep 2; $job = Invoke-RestMethod "http://localhost:8000/api/jobs/$($job.id)" } while ($job.status -ne "done")
$job.files | Select-Object name, status, output_name, output_width, output_height, error | ConvertTo-Json

# 3a. Download everything as one ZIP
Invoke-WebRequest "http://localhost:8000/api/jobs/$($job.id)/zip" -OutFile C:\pics\upscaled.zip

# 3b. ...or each finished file
foreach ($f in $job.files | Where-Object status -eq "done") {
    Invoke-WebRequest "http://localhost:8000/api/jobs/$($job.id)/files/$($f.id)" -OutFile "C:\pics\$($f.output_name)"
}
```

| Endpoint | Purpose |
|---|---|
| `POST /api/jobs` | multipart: `files` (1-20), `scale` (2 or 4). Returns the job (`id`, `files[]`) |
| `GET /api/jobs/{id}` | `status`, `progress`, and per file: `id`, `name`, `status`, `error`, sizes, `output_name` |
| `GET /api/jobs/{id}/files/{file_id}` | the upscaled image |
| `GET /api/jobs/{id}/original/{file_id}` | the original upload |
| `GET /api/jobs/{id}/zip` | ZIP of all finished images |
| `GET /api/health`, `GET /api/config` | server status, limits |

Errors return JSON `{"detail": "..."}`: 413 = file too large, 415 = not JPG/PNG/WEBP,
422 = bad scale, too many files or image too large, 404 = unknown or expired job,
409 = file not finished yet. Interactive API docs: http://localhost:8000/docs.

## 6. Limits and timing

- Max **10 MB** per file, **20 files** per batch.
- Longest input side: **4096 px for 2x**, **2048 px for 4x** (outputs up to ~8K).
  For bigger images, use 2x, or tell the user the image is too large.
- Jobs and their files are deleted from the server **1 hour** after they finish,
  so download promptly. Files already saved on disk are not affected.
- Images are processed one at a time. On a **GPU** a typical photo takes seconds.
  On the **CPU** a 1-megapixel image at 4x can take several minutes, so warn the
  user before large CPU batches and use a larger `timeout_seconds`.
- Limits can be changed with environment variables set before `start.ps1`:
  `MAX_FILE_MB`, `MAX_FILES_PER_JOB`, `MAX_INPUT_SIDE_2X`, `MAX_INPUT_SIDE_4X`, `JOB_TTL_SECONDS`.

## 7. Troubleshooting

| Symptom | Fix |
|---|---|
| "running scripts is disabled on this system" | Run scripts as `powershell -ExecutionPolicy Bypass -File .\script.ps1` |
| `start.ps1` says not ready / exits 1 | Read `backend\server.log`. Port 8000 busy: `.\start.ps1 -Background -Port 8010` and set `UPSCALER_API_URL=http://localhost:8010` in the MCP config |
| "Cannot reach the upscaler API" | Server not running: `.\start.ps1 -Background` |
| `/api/health` shows `lanczos` | Model weights missing: re-run `setup.ps1` (it downloads them) |
| CUDA out of memory | Stop, `$env:TILE_SIZE = "256"`, start again (smaller tiles use less VRAM) |
| Very slow | It is on the CPU (`CUDA available: False`). Install NVIDIA drivers, re-run `setup.ps1` without `-Cpu` |
| MCP tools don't appear | Claude Code: run `claude` from this folder and approve the server. Claude Desktop: re-run `setup.ps1 -RegisterClaudeDesktop` and restart it fully (also from the system tray) |
| Tests | `backend\.venv\Scripts\python.exe -m pip install pytest` then `cd backend; .venv\Scripts\python.exe -m pytest` |
